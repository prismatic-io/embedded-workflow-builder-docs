[Adobe Commerce (Magento)](https://business.adobe.com/products/magento/magento-commerce.html#) is an open-source e-commerce platform.

Use the Adobe Commerce component to manage the Products, Orders, Customers, and Transactions in an Adobe Commerce store.

## API Documentation

This component was built using the [Adobe Commerce REST API Overview](https://developer.adobe.com/commerce/webapi/rest/).

## Connections

### API Access Key (Deprecated) {#adobecommerceapikey}

Authenticate with Adobe Commerce using an API Access Key and Secret.

:::warning[Deprecated]
This connection authenticates against the Adobe Commerce Marketplace Developer API, the portal used to submit and manage extensions. It does not authenticate against a merchant's store, so it cannot read or write store data such as orders, products, customers or transactions. Use the **OAuth 1.0a** connection for store data.
:::

The Marketplace EQP API uses a two-step process to authenticate a client application and authorize access to resources:

1. Using the [API access key](https://developer.adobe.com/commerce/marketplace/guides/eqp/v1/access-keys), obtain a session token.
2. Create the API access key from one, or both, of the **Marketplace Developer Portal** user interfaces:
   1. production - [https://commercedeveloper.adobe.com](https://commercedeveloper.adobe.com/)
   2. sandbox - [https://commercedeveloper-sandbox.adobe.com](https://commercedeveloper-sandbox.adobe.com/)
3. From the **Marketplace Developer Portal**, sign in, click on the account name (top, right corner), and choose either the **Account Information** or the **Marketplace Profile** link.
4. From the left-hand side navigation menu, click on **Manage API Keys**.
5. Click **Create API Access Key**.
6. In the "Create New API Key" dialog, enter an **API Key Name**. This name is for internal reference only. Then, click **Continue**.
7. The API access key consists of two values, an **Application ID** and an **Application Secret**. Enter both into the connection configuration, along with the **Use Production Environment** toggle set to match the portal (production or sandbox) used to create the key.

#### Configure the Connection

- **Application ID**: the application ID generated by the **Marketplace Developer Portal** when the API access key is created.
- **Application Secret**: the application secret generated alongside the Application ID.
- **Use Production Environment**: a boolean toggle. Set to `true` to use the production environment (`https://commercedeveloper-api.adobe.com`); set to `false` to use the sandbox environment (`https://commercedeveloper-sandbox-api.adobe.com`). Defaults to `false` (sandbox).

| Input                      | Comments                                                                                                                                                                                                                                                                                                              | Default |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| Application ID             | The application ID half of a Marketplace API access key. Generate one in the Marketplace Developer Portal under your account name > **Account Information** > **Manage API Keys**. See [API access keys](https://developer.adobe.com/commerce/marketplace/guides/eqp/v1/access-keys#what-is-an-api-access-key).       |         |
| Application Secret         | The application secret issued alongside the application ID above, from the same Marketplace API access key. The key can be regenerated or deleted at any time under **Manage API Keys**. ### OAuth 1.0a {#adobecommerceoauth1}

Authenticate with an Adobe Commerce store using an integration's OAuth 1.0a credentials.

**OAuth 1.0a** authenticates requests against a merchant's own Adobe Commerce store, and is the authentication method to use for reading and writing store data such as orders, products, customers and transactions.

An integration activated in the Adobe Commerce Admin issues four credentials: a consumer key, a consumer secret, an access token and an access token secret. There is no login screen and no token to request: the four values sign every request directly, and neither secret is ever transmitted to the store.

#### Prerequisites

- A merchant-hosted Adobe Commerce store reachable over HTTPS. A store reachable only over plain HTTP is not supported.
- An administrator account with permission to create integrations

Adobe Commerce as a Cloud Service authenticates through Adobe's Identity Management System instead and is not supported by this connection. Refer to [Authentication in Adobe Commerce as a Cloud Service](https://developer.adobe.com/commerce/webapi/rest/authentication/).

#### Setup Steps

To create an integration and obtain its credentials:

1. Log in to the Adobe Commerce Admin.
2. Navigate to **System** > **Extensions** > **Integrations**.
3. Click **Add New Integration** and enter a **Name**.
4. Open the **API** tab and grant the resource access the integration requires. Reading orders, products and customers requires at least **Sales**, **Catalog** and **Customers**.
5. Click **Save**.
6. Click **Activate** on the new integration, review the requested access, and click **Allow**.
7. Copy all four values from the **Integration Tokens for Extensions** dialog.

The four values are shown only at activation, so they must be copied before the dialog is closed. Lost credentials are replaced by reauthorizing the integration, which issues a new set. The credentials do not expire. They stay valid until the integration is deactivated or reauthorized.

Refer to [Integrations](https://experienceleague.adobe.com/en/docs/commerce-admin/systems/integrations) for more information on creating and activating an integration, and to [Authentication](https://developer.adobe.com/commerce/webapi/get-started/authentication/) for Adobe's description of the OAuth 1.0a method.

#### Configure the Connection

Create a connection of type **OAuth 1.0a** and configure the following fields:

- Enter the store's base URL into **Store URL**, without a trailing slash and without the `/rest` path (for example, `https://www.example.com`).
- Enter the four values copied at activation into **Consumer Key**, **Consumer Secret**, **Access Token** and **Access Token Secret**.
- Optionally set **Store Code**. It defaults to `default`, the store view code a single-store installation ships with, and forms the `<store_code>` segment of the `/rest/<store_code>/V1` request path. Change it only on a store that serves multiple store views.

| Input               | Comments                                                                                                                                                                                                                         | Default |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| Store URL           | The base URL of the Adobe Commerce store, without a trailing slash and without the `/rest` path.                                                                                                                                 |         |
| Consumer Key        | The consumer key shown when an integration is activated under **System > Extensions > Integrations** in the Adobe Commerce Admin. See [Authentication](https://developer.adobe.com/commerce/webapi/get-started/authentication/). |         |
| Consumer Secret     | The consumer secret issued alongside the consumer key above. It is used to sign each request and is never sent to the store.                                                                                                     |         |
| Access Token        | The access token issued when the integration was activated. Unlike a bearer token it is not sufficient on its own: it identifies the integration, and the access token secret below proves possession.                           |         |
| Access Token Secret | The access token secret issued alongside the access token above. It is used to sign each request and is never sent to the store.                                                                                                 |         |
| Store Code          | The store view code requests are scoped to, used as the `<store_code>` segment of `/rest/<store_code>/V1`. Leave as `default` unless the store serves multiple store views.                                                      | default |

## Triggers

### New and Updated Records {#pollchangestrigger}

Checks a Magento resource collection (orders, customers, or products) on a configured schedule for records whose `updated_at` is at or after the last poll. Records whose `created_at` is also after the last poll are included in the payload's `body.data.created` array; older records modified since the last poll are included in `body.data.updated`.

| Input                | Comments                                                                                                                                                                                                                                                                            | Default |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| Connection           | The Adobe Commerce connection to use.                                                                                                                                                                                                                                               |         |
| Resource Type        | The Magento resource collection to poll for new and updated records.                                                                                                                                                                                                                | orders  |
| Look-back Date       | The date the initial sync starts from, in YYYY-MM-DD format. Cannot be a future date. Leave empty to start from the first recurrence with no backfill. When set, the initial sync seeds each record modified on or after this date once, ignoring the field and visibility filters. |         |
| Show New Records     | When true, records whose `created_at` falls after the last poll are included in the payload's `body.data.created` array.                                                                                                                                                            | true    |
| Show Updated Records | When true, records whose `updated_at` falls after the last poll but were created earlier are included in the payload's `body.data.updated` array.                                                                                                                                   | true    |
